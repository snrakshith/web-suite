## Difference between Liskov Substitution Principle (LSP) & Open/Closed Principle (OCP)

- The Liskov Substitution Principle (LSP) and the Open/Closed Principle (OCP) are closely related, but they focus on different aspects of software design.
- Let's clarify their differences using the examples provided, simplifying the concepts for better understanding.

### Liskov Substitution Principle (LSP)

**Core Idea:**  
LSP is about ensuring that subclasses or derived components can be used in place of their parent class or base components without breaking the application. The key is **behavioral consistency**—the subclass should behave in a way that the base class expects.

**Example Recap:**

- **Base Component:** `Button`
- **Derived Component:** `IconButton`

- In this example, `IconButton` can be used wherever `Button` is expected.
- The behavior (clicking the button) remains consistent, so the substitution doesn't break the application.

**Simplified Understanding:**  
LSP ensures that when you extend a component, the new component behaves as expected when used in place of the original. If you replace a `Button` with an `IconButton`, it should work the same way without unexpected side effects.

### Open/Closed Principle (OCP)

**Core Idea:**  
OCP is about making components that are **open for extension** but **closed for modification**. This means you can add new features or behaviors to a component without altering its existing code, thereby avoiding the risk of introducing bugs into existing functionality.

**Example Recap:**

- **Base Component:** `Notification`
- **Extensions:** `SuccessNotification`, `ErrorNotification`

- In this example, `Notification` is extended to create `SuccessNotification` and `ErrorNotification` without modifying the original `Notification` component.
- New functionality is added through extension rather than by changing the base component.

**Simplified Understanding:**  
OCP ensures that your components can grow and evolve with new features or behaviors by adding new components or functionalities instead of changing the existing ones. This keeps the existing code stable while allowing for easy extension.

### Key Differences

- **Focus:**

  - **LSP** focuses on **behavioral consistency** when extending components. It ensures that derived components can be substituted for their base without breaking the system.
  - **OCP** focuses on **extensibility**. It encourages adding new features or variations without modifying the original, thereby keeping the codebase stable.

- **When to Use:**
  - Use **LSP** when you want to ensure that new components behave correctly when used in place of an existing component.
  - Use **OCP** when you need to extend functionality without touching or risking the stability of existing code.

### Simplified Example for Both

Imagine you have a `Vehicle` component and you create a `Car` component that extends `Vehicle`.

- **LSP:**
  - `Car` should be usable anywhere a `Vehicle` is expected. If `Vehicle` has a `drive` method, `Car` should have a `drive` method that works similarly.
- **OCP:**
  - If you need to add a new type of `Vehicle`, say `Bike`, you should do this by creating a new `Bike` component rather than changing the existing `Vehicle` component.

By following LSP, you ensure that the new `Car` behaves as expected when used as a `Vehicle`. By following OCP, you can add `Bike` without modifying `Vehicle`, ensuring the original code remains untouched and stable.
